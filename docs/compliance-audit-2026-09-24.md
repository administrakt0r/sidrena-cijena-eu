## Concrete changes made during this audit

- Corrected the mistaken post-reference rule: a new item's applicable anchor is its evidenced first-offer price/date, not “no anchor.” Missing anchors still block list publication.
- Made a recorded post-reference first-offer date valid when it is on/after that item's baseline and not in the future; the general/legacy fixed-date validation remains for items already present at baseline.
- Added a visible first-offer/reference date beside the storefront anchor and a date field (`datum_sidrene_cijene` in CSV; `datumSidreneCijene` in XML). The date is also already exposed by the public REST representation.
- Added regression coverage for first-offer anchor acceptance and aligned CSV/XML examples, schema docs and operation instructions.
- Scheduled daily generation 15 minutes before the configured deadline so a regular server scheduler has a buffer; each scheduled run forces a dated publication even when list contents are unchanged. Corrected inaccurate cron guidance (a 06:00 one-off run cannot execute an event scheduled for 08:00).
- Queued service-price regeneration immediately and deferred WooCommerce display-hook registration until `init`, avoiding translated settings being evaluated before the plugin text domain loads.
- Added priced WooCommerce variations as individual list offers, generated stable `WC-{product_id}` / `WC-{parent_id}-V{variation_id}` codes when SKUs are empty, and passed each selected variation's anchor/date to the storefront. An unpriced, non-purchasable 10L variation is excluded rather than assigned a guessed price.
- Tightened filename generation and validation: an address/city is required, and malformed or addressless filenames are rejected. The location compliance check reports missing street/city.
- In this local development database only, recorded 893 offer anchors dated 10 September from catalog values last modified by 25 August 2026 and 119 variable-parent “from” anchors using each product's lowest variation value. This snapshot is useful for local rendering and list development; it is not evidence of the actual first-offer/historical price and must be verified against merchant records before production use.

## Market reference: mojacijena.hr

Its public marketing page claims guided onboarding, WooCommerce and standalone catalog support, CSV/XML, archive links, per-service/product pricing, daily publication checks/alerts and managed setup. Useful feature ideas: guided completeness checks, prominent archive access, and external monitoring/alerts. These are vendor claims, not independently verified product behavior or law. This plugin already has CSV/XML publication, archive/REST endpoints and admin validation; it **does not provide an external uptime monitor that alerts a third party**. Monitoring must be supplied by the merchant/operator or added as a separate operational service.
